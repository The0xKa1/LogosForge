# 需求分析

## 子问题分解

系统需要把多本教材变成可教学、可追溯、可压缩的统一知识库。核心子问题包括：多格式教材解析、知识点粒度定义、单书知识图谱构建、跨教材重复/互补/缺失识别、30% 压缩控制、RAG 精准问答和教师反馈迭代。

## 知识点粒度

知识点定义为“可被教师独立讲授、考核或连接前后内容的最小教学单元”。它不等同于文本 chunk：一个 chunk 可能包含多个知识点，一个知识点也可能引用多个 chunk。

首版支持六类知识点：概念、方法、现象、机制、结构、应用。抽取时按章节处理，避免一次性上下文过长。

## 重复判定标准

重复判定采用多层标准：

- 名称或别名相似，例如中文术语、英文缩写、同义表达。
- 定义等价，即核心含义和教学边界一致。
- 教学用途一致，即在课程链路中承担同样作用。
- 关系一致，即前置依赖、包含、并列或应用关系没有冲突。

只名称相似但定义不同的节点不自动合并，交由 LLM 或教师反馈二次确认。

## 互补与缺失

互补表示同一知识点在不同教材中提供不同视角，例如基础结构、正常功能、异常机制和临床应用。缺失表示某教材没有覆盖整合大纲中的必要知识点，或只提到术语但缺少可教学解释。

## 教学连贯性保障

整合稿默认按“基础概念 -> 前置依赖 -> 核心机制 -> 对比关系 -> 应用场景”组织。合并重复节点时保留 prerequisite 关系和原文证据，避免压缩导致教学链路断裂。

## 30% 压缩比计算

分母为原始有效正文字符数，排除封面、版权、目录、前言、作者介绍、参考文献、索引等非教学正文。分子为整合精华正文字符数，不包含引用列表、UI 文案或报告说明。

约束公式：

```text
整合后正文字符数 <= 原始有效正文字符数 * 0.30
```

## RAG 分块策略

RAG 使用 500–800 字 chunk，50–100 字 overlap。该粒度可以兼顾中文教材段落完整性和 top-k 检索精度：太短会丢失定义上下文，太长会降低召回精度并增加生成成本。每个 chunk 保留教材名、章节和起始页码。
