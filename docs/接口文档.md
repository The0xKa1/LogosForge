# 接口文档

所有接口基地址：`http://localhost:8000`

## POST /api/textbooks/upload

上传一个或多个教材文件。

**Content-Type**: `multipart/form-data`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `files` | File[] | 是 | 支持 PDF / Markdown / TXT / DOCX，可多选 |

**curl 示例**：

```bash
curl -X POST http://localhost:8000/api/textbooks/upload \
  -F "files=@生理学.pdf" \
  -F "files=@病理学.pdf"
```

**响应** `200`：

```json
{
  "textbooks": [
    {
      "textbook_id": "book_a1b2c3d4e5",
      "filename": "生理学.pdf",
      "file_format": "pdf",
      "status": "uploaded"
    }
  ]
}
```

## POST /api/textbooks/parse

解析已上传的教材，抽取章节结构和有效正文。跳过已解析（有 chapters）的教材。

**Content-Type**: `application/json`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `textbook_ids` | string[] | 否 | 指定要解析的教材 ID 列表，为空则解析所有已上传的教材 |

**请求**：

```json
{ "textbook_ids": ["book_a1b2c3d4e5"] }
```

**响应** `200`：

```json
{
  "textbooks": [
    {
      "textbook_id": "book_a1b2c3d4e5",
      "title": "生理学",
      "status": "completed",
      "chapters": [
        { "title": "第一章 细胞的基本功能", "page_start": 1, "char_count": 15230 }
      ],
      "effective_chars": 450000
    }
  ]
}
```

## POST /api/graph/build

构建单本或全部已解析教材的知识图谱。支持 LLM/正则模式切换。

**Content-Type**: `application/json`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `textbook_ids` | string[] | 否 | 指定要构建图谱的教材 ID，为空则构建全部已解析教材 |
| `use_llm` | boolean | 否 | 是否使用 LLM 抽取知识点（默认 true，false 则使用正则 fallback） |

**请求**：

```json
{
  "textbook_ids": ["book_a1b2c3d4e5"],
  "use_llm": true
}
```

**响应** `200`：

```json
{
  "graph": {
    "nodes": [
      {
        "id": "node_x1y2z3",
        "name": "炎症",
        "definition": "具有血管系统的活体组织对损伤因子所发生的防御反应",
        "category": "现象",
        "chapter": "第四章 炎症",
        "page": 78,
        "frequency": 1
      }
    ],
    "edges": [
      {
        "source": "node_a",
        "target": "node_b",
        "relation_type": "prerequisite",
        "description": "学习B前需理解A"
      }
    ]
  },
  "decisions": [],
  "integrated_text": "【炎症】具有血管系统的活体组织..."
}
```

## POST /api/graph/merge

跨教材对齐，输出整合图谱和决策。无需请求参数。

**响应** `200`：

```json
{
  "graph": { "nodes": [...], "edges": [...] },
  "decisions": [
    {
      "action": "merge",
      "affected_nodes": ["node_a", "node_b"],
      "result_node": "merged_炎症",
      "reason": "两本教材覆盖同一概念",
      "confidence": 0.86
    }
  ],
  "integrated_text": "...",
  "compression_ratio": 0.27
}
```

## POST /api/rag/index

将当前已解析教材的章节切分为 chunk 并写入 ChromaDB 向量索引。无需请求参数。

**响应** `200`：

```json
{
  "indexed_textbooks": 7,
  "chunk_count": 5562
}
```

## POST /api/rag/query

RAG 精准问答：检索相关 chunk 并生成带引用的回答。

**Content-Type**: `application/json`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `question` | string | 是 | 用户问题 |

**请求**：

```json
{ "question": "炎症的核心概念是什么？" }
```

**响应** `200`：

```json
{
  "answer": "炎症是具有血管系统的活体组织对损伤因子所发生的防御反应 [病理学, 第四章 炎症, 第 78 页]。其基本病理变化包括变质、渗出和增生...",
  "citations": [
    {
      "textbook": "病理学",
      "chapter": "第四章 炎症",
      "page": 78,
      "relevance_score": 0.92
    }
  ],
  "source_chunks": ["炎症是具有血管系统的活体组织..."]
}
```

## GET /api/rag/status

查询当前 RAG 索引状态。无需请求参数。

**响应** `200`：

```json
{
  "backend": "chroma",
  "available": true,
  "chunk_count": 5562,
  "embedding_model": "BAAI/bge-large-zh-v1.5",
  "db_dir": "/path/to/chroma_db"
}
```

## POST /api/teacher/chat

教师多轮对话：分析教师反馈，可能修改整合决策。

**Content-Type**: `application/json`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `message` | string | 是 | 教师反馈文本 |
| `decision_id` | string | 否 | 关联的决策 ID（可选） |

**请求**：

```json
{
  "message": "我觉得免疫应答不应该被删除，请保留",
  "decision_id": "merge_xxx"
}
```

**响应** `200`：

```json
{
  "reply": "您说得对，'免疫应答'确实是免疫学的核心概念。我已将其从删除改为保留。",
  "decisions": [...],
  "chat_history": [...]
}
```

## POST /api/report/generate

生成整合报告并写入 `report/整合报告.md`。无需请求参数。

**响应** `200`：

```json
{
  "path": "/path/to/report/整合报告.md",
  "content": "# 学科知识整合报告\n..."
}
```

## GET /api/state

获取当前项目完整状态。无需请求参数。

**响应** `200`：返回 `ProjectState` 完整 JSON（包含 textbooks、graph、decisions、chunks、chat_history、integrated_text 等）。

## 错误响应

所有接口在参数错误或服务异常时返回标准错误格式：

**400 Bad Request** — 请求参数不合法：

```json
{ "detail": "No parsed textbooks available" }
```

**422 Unprocessable Entity** — 请求体格式错误（Pydantic 校验失败）：

```json
{
  "detail": [
    {
      "loc": ["body", "question"],
      "msg": "field required",
      "type": "value_error.missing"
    }
  ]
}
```

**500 Internal Server Error** — 服务端异常：

```json
{ "detail": "Internal server error" }
```

## 实现说明

- 服务读取 `backend/.env` 中的 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`。
- `/api/rag/index` 会将当前已解析教材 chunk 写入本项目 `backend/chroma_db`。
- 检索优先使用 ChromaDB + `EMBEDDING_MODEL`，默认模型为 `BAAI/bge-large-zh-v1.5`。
- 若 Chroma 或 embedding 模型不可用，自动回退到本地词项检索。
- 接口兼容 OpenAI Chat Completions 格式。
- 检索 top-5 chunk 后，将教材名、章节、页码和正文注入 prompt。
- 模型必须只基于上下文回答，并使用 `[教材名称, 章节, 第 X 页]` 格式引用。
- 如果缺少 key、依赖或模型调用失败，系统自动回退到本地检索摘要。
